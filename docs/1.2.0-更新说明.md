# Reopen 1.2.0 更新内容

相对 GitHub 上的 v1.1.0，本版新增**失败诊断**，并统一去掉界面滚动条。

## 失败诊断：从「退出码 1」到「卡在哪、该找谁」

启动失败时不再只给一句技术黑话，而是四层信息：

- **归属徽章**——一眼看出这事该谁管：我能修 / 电脑上缺东西 / 项目自己的问题 / 要连外部服务 / 没认出来
- **一句人话**——说清是什么毛病
- **定位行**——抠出具体对象（哪个命令、哪个包、哪个端口）
- **下一步**——能一键修的给按钮；修不了的给做法说明；实在认不出的，一键复制完整日志

诊断规则从主进程抽成独立的纯函数模块（`src/main/diagnose.ts`），14 条规则覆盖：端口被占、依赖没装、跨平台拷贝依赖、命令不存在、启动脚本缺失、Docker 没开、Python 缺包、依赖版本冲突、网络不通、缺配置、数据库没连、磁盘满等。

### 本版如实说清的两类问题

这两类**刻意不给一键修复按钮**——因为在当前状态下点了也必然失败，只会让人白点：

- **macOS 权限挡住项目目录**：项目放在「下载 / 桌面 / 文稿」时，程序连自己在哪个目录都读不到，`npm install` 也写不进去。卡片会说明该把项目挪到哪、或去哪里授权。
- **项目代码或文件本身的问题**：代码有语法错误、缺入口文件这类，环境修不好，卡片会直说是项目自身的问题。

### 顺带修掉

- 诊断不再被上一次失败的残留日志误导（此前第二次失败可能读到上一次的报错，得出错误结论）。
- 失败原因留痕到 `service-logs/<项目 id>/diagnosis.log`，事后可查当时是怎么判的。

## 界面

- **全局去掉滚动条**：全项目不再出现可见滚动条，内容照常滚动（触控板 / 滚轮 / 拖拽均不受影响）。此前主内容区和菜单栏面板还残留滚动条。

## 验证

- `npm test`：新增诊断引擎的黄金文本测试（16 例，含 2 个本机真实报错样本 + 规则优先级断言）；原有 8 项回归全绿。
- `npm run typecheck`、`npm run lint`：静态检查。
- 用真实失败日志端到端验证过诊断结果。

仅提供 Apple Silicon macOS 安装包；使用本地签名，未进行 Apple Developer 公证。
