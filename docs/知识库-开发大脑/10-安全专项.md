## 第 10 章：安全专项

### 10.1 是什么

安全回答一个问题：**"这东西会被怎么攻破、怎么防？"**

### 10.2 核心概念（人话版）

| 名词                       | 人话                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| 加密 Encryption            | 把内容搅乱成只有拿钥匙的人能看懂                                                         |
| 哈希 Hash                  | 单向"指纹计算"：同一个东西算出的指纹永远一样，但指纹推不回原物（存密码用哈希，不用明文） |
| 密钥 Key / Secret          | 密码/凭证的总称（数据库密码、API 密钥）                                                  |
| Token 令牌                 | 登录后发的"通行证"，带着它才证明你登录过                                                 |
| HTTPS                      | 传输加密的网页协议，防偷听篡改                                                           |
| XSS（跨站脚本攻击）        | 坏人往你的页面里塞假代码，偷访客信息                                                     |
| SQL 注入                   | 坏人往输入框里塞数据库命令，偷整张表                                                     |
| 最小权限原则               | 程序只申请它必须有的权限，多一个都是风险                                                 |
| 依赖漏洞扫描               | 检查借来的库有没有已知安全洞（npm 生态命令：`npm audit`）                                |
| 供应链攻击                 | 坏人攻破某个依赖库，间接感染所有用它的人（所以依赖要少、要审查）                         |
| 脱敏 Desensitization       | 日志/截图里把手机号、密码打码                                                            |
| OAuth                      | 第三方登录的标准协议："用微信登录本站"——本站不碰你的密码，只拿通行证                     |
| 2FA（双因素认证）          | 登录要过两道关：密码 + 短信/动态码，防密码泄露后被冒用                                   |
| RBAC（基于角色的权限管理） | 多人系统里按角色发权限：管理员能删、编辑能改、访客只能看                                 |
| 渗透测试 Penetration Test  | 请安全专家像黑客一样攻击自己的系统，找出漏洞                                             |

### 10.3 桌面应用的安全要点

| 要点           | 人话                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 签名防篡改     | 有签名的应用被改过就露馅，用户知道它"原装"                           |
| 权限申请克制   | macOS 会在应用访问敏感位置时弹窗询问（TCC 权限体系），设计上尽量少碰 |
| 不联网就不泄露 | 单机工具最大的安全优势：数据不出本机，攻击面天然小                   |
| 更新通道安全   | 自动更新必须走 HTTPS，防止更新包被调包                               |

### 10.4 常见误区

- ❌ **"我的小项目没人攻击"**——依赖漏洞和供应链攻击专挑小项目下手（因为没人管）。
- ❌ **密钥写进代码里提交**——代码一旦公开（开源），密钥等于全世界可见。
- ❌ **收集用不到的数据**——多存一份用户数据就多一份责任。

### 10.5 数据合规（产品的法律底线）

| 名词                             | 人话                                                             |
| -------------------------------- | ---------------------------------------------------------------- |
| 个保法（PIPL）                   | 中国《个人信息保护法》：收集用户信息要告知、要同意、要能删除     |
| GDPR                             | 欧盟通用数据保护条例：全球最严的数据法规（服务欧洲用户就要遵守） |
| 隐私政策 Privacy Policy          | 告诉用户"我收集什么、拿来干什么"的声明文档——收集数据的产品必备   |
| 用户协议 ToS（Terms of Service） | 使用规则和服务条款                                               |

**给个人项目的底线**：能不收集就不收集；收集了就要有隐私政策；用户要求删除就必须能删。

### 10.6 攻击面与防御原理

#### 加密的两大门派

| 类型       | 人话                                       | 用途                                                                         |
| ---------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| 对称加密   | 一把钥匙开门又关门（钥匙要保密）           | 加密大量数据（文件、数据库内容）                                             |
| 非对称加密 | 两把钥匙：公钥加密、私钥解密（公钥可公开） | 密钥交换、数字签名（HTTPS 就是两者配合：先用非对称交换钥匙，再用对称传数据） |

#### 数字签名：怎么证明"消息没被改过"

三步人话版：

1. 发送者对消息算一个**指纹**（哈希）
2. 用自己的**私钥**给指纹盖章（签名）
3. 接收者用发送者的**公钥**验证章的真伪——指纹对得上且章是真的，消息就没被篡改

应用：HTTPS 证书、dmg 签名、JWT、Git 提交签名——都是这个原理。

#### 中间人攻击（MITM）

人话：你和服务器之间藏了个"假前台"，你的请求全被他转发（他看得见、改得掉）。HTTPS 就是防这个：证书证明"你连的确实是真服务器，不是假前台"。**所以"证书不安全"的警告不要点忽略。**

#### CSRF 跨站请求伪造

人话：你登录了银行网站 A，又打开恶意网站 B——B 悄悄以"你的身份"向 A 发起请求（因为你浏览器里带着 A 的登录凭证）。防御：请求带一次性令牌校验，或服务端校验请求来源。

#### 上线前安全检查清单（逐项可打勾）

- [ ] 依赖扫描过（`npm audit`），无已知高危漏洞
- [ ] 密码不落明文：存哈希（加盐）；密钥不进代码库（放 .env / Keychain）
- [ ] HTTPS 全站启用，证书有效
- [ ] 日志无敏感信息（密码、手机号、身份证脱敏）
- [ ] 权限最小化：程序只用它需要的权限，不要多余的
- [ ] 有隐私政策页（收集数据的产品）
- [ ] 桌面应用：签名/公证到位（见[第 5 章 5.3.3](05-开发阶段.md)）
