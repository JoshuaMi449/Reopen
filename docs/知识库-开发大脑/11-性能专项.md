## 第 11 章：性能专项

### 11.1 是什么

性能回答一个问题：**"用起来快不快、顺不顺、省不省？"**

### 11.2 性能指标（人话版）

| 指标 | 人话 |
|---|---|
| 启动时间 Launch Time | 双击图标到窗口出现，几秒算及格（桌面应用 3 秒内良好） |
| 响应时间 Response Time | 点一下到有反应的时间（100ms 内感觉"瞬间"） |
| 内存占用 Memory Usage | 吃多少内存（占用过高会拖慢整台电脑） |
| CPU 占用 | 吃多少算力（后台空转还吃 CPU 就是有毛病） |
| FPS 帧率 | 动画每秒画几帧（60 帧顺滑，低于 30 帧感觉卡） |
| 卡顿 Jank | 界面一顿一顿的现象 |

### 11.3 优化手段（人话版）

| 手段 | 人话 |
|---|---|
| 缓存 Cache | 常用东西提前放抽屉，省得每次现找 |
| 异步 Async | 慢活放后台干，界面照常响应（快递在途，你继续干别的） |
| 懒加载 Lazy Loading | 用到再加载，不提前扛所有东西 |
| 压缩 Compression | 文件瘦身，传得快占得少 |
| 批处理 Batching | 十个请求合并成一次发，省十次来回 |

### 11.4 常见误区

- ❌ **提前优化**——"我猜这里慢，先优化了再说"。铁律：先测量出真的慢，再优化慢的地方。
- ❌ **用卡顿换功能**——功能再多，用起来难受就全白搭。
- ❌ **只在顶级电脑上测试**——用户的电脑一般没你的好。

### 11.5 性能排查的思维框架

**怎么测量**（先有数再谈优化）：

- 网页/Electron 界面：开发者工具 → Performance 面板，录制操作看每段耗时
- 桌面应用：系统自带的"活动监视器"看内存/CPU 曲线
- 铁律：**先测出"哪里慢、慢多少"，再动手**——没有数据的优化都是猜

**内存泄漏的识别与排查**：

| 现象 | 含义 |
|---|---|
| 内存只涨不降 | 用着用着越来越卡，重启才恢复——典型泄漏 |
| 常见成因 | 定时器/监听器用完没清理、全局变量越存越多、闭包无意中锁住了大对象 |
| 排查口诀 | "谁在一直累积，谁就是元凶"——观察哪个操作后内存涨了且不回落 |

**"卡顿→定位→修复→复测"闭环**：先描述清楚"什么时候卡"（打开时？滚动时？点某按钮后？）→ 按场景测量 → 定位最慢的一段 → 修复 → 用同一测量方式复测确认变快。没有复测的优化等于没做。
