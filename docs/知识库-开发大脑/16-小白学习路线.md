## 小白学习路线：从"什么都不懂"到"能主导一个产品"

> 目标不是成为写代码的程序员，而是成为**能听懂、能判断、能主导**的产品负责人。三条路线按你的目标选：

### 路线一：我要马上开发一个产品（1~2 天速成）

适合：手头有想法，想立刻开始 vibe coding。

| 顺序 | 读什么 | 读到什么程度 | 用时 |
|---|---|---|---|
| 1 | [01-全景总览](01-全景总览.md) | 记住"八大阶段"和"单人+AI 怎么分工"，知道自己是干产品+测试的 | 20 分钟 |
| 2 | [02-需求阶段](02-需求阶段.md) | **精读** 2.2 PRD 详解——你写的第一份文档就是它 | 1 小时 |
| 3 | [05-开发阶段](05-开发阶段.md) 的 5.4 脚本与命令文件 | 搞懂 `npm run xxx` 是什么、`.env` 是什么——AI 让你跑命令时你能看懂 | 40 分钟 |
| 4 | [17-AI辅助开发](17-AI辅助开发.md) | **精读**：怎么给 AI 布置任务、怎么验收、怎么防幻觉——这是你每天都要做的事 | 40 分钟 |
| 5 | [08-发布阶段](08-发布阶段.md) | 知道 dmg 怎么打、GitHub Release 怎么发 | 30 分钟 |
| 6 | 开发中随时查 [14-Glossary](14-Glossary-A-基础概念.md) | 遇到不懂的词当场查 | 碎片时间 |

**检验标准**：你能写出自己的 PRD，AI 说的每个名词你能听懂 70%。

### 路线二：我要理解完整流程（1 周系统学）

适合：想真正搞懂"一个产品从 0 到 1 要做什么"，和程序员对话不怯场。

| 顺序 | 读什么 | 重点 |
|---|---|---|
| 1 | [00-如何使用本文档](00-如何使用本文档.md) → [01-全景总览](01-全景总览.md) | 建立地图 |
| 2 | [02-需求](02-需求阶段.md) → [03-设计](03-设计阶段.md) | **产品的世界**：PRD、优先级、UI 组件名词——3.6 组件表和 3.7 页面类型是重点，以后和设计师/开发对话全靠它 |
| 3 | [04-技术方案](04-技术方案.md) | 选型三标准、架构、数据库、API——为什么技术要"提前想" |
| 4 | [05-开发](05-开发阶段.md) | **程序的世界**：前端三件套、React、Electron 双进程、Git——每节都有人话比喻，不懂的词当场查 Glossary C/H（前端/桌面），Git 类词查 B、质量类查 F |
| 5 | [06-测试](06-测试阶段.md) → [07-运维](07-运维阶段.md) → [08-发布](08-发布阶段.md) | 验收、上线、发布——你作为产品负责人要在这里把关 |
| 6 | [09-运营](09-运营与迭代.md) → [10-安全](10-安全专项.md) | 迭代节奏、合规红线 |
| 7 | [17-AI辅助开发](17-AI辅助开发.md) | 贯穿全程的协作方法——越早读越好 |
| 8 | [11-性能](11-性能专项.md) / [12-兼容](12-兼容与国际化.md) / [13-数据](13-数据专项.md) | 按需 |
| 9 | [14-Glossary A~H](14-Glossary-A-基础概念.md) | 通读一遍当复习，每词 3 秒 |

**检验标准**：随便翻开一个技术文章标题，你能说出它在讲哪个阶段的事。

### 路线三：我要查词（随时用）

- 知道中文名不知道英文名 → 在 14-Glossary 各文件里搜中文
- 知道英文缩写 → 直接定位对应类（A 基础 / B 流程 / C 前端 / D 后端 / E 运维 / F 质量 / G 设计 / H 桌面）
- 想了解一个主题的全貌 → 读对应正文章节，章节里的名词再跳到 Glossary

### 三条心法（贯穿所有路线）

1. **名词是普通话**：需求说"弹窗"、设计说"Modal"、开发说"Dialog"——名词统一了，返工就少。这就是 Glossary 存在的意义。
2. **AI 干活，你做判断**："要做什么、好不好用"永远由人拍板，AI 负责执行细节。
3. **边做边查**：不需要先背完再动手。遇到不懂的，当场查，查完继续——知识网就是这么用的。
