## 第 14 章：专业术语速查表（Glossary）

> 本章是全文档的"字典"：开发中遇到任何不懂的词，来这查。
> 分 8 类，每类内英文词按字母排序在前、中文词按拼音排序在后。正文各章详解过的词这里只留一句话人话。

### A. 基础概念

> 本类词条：英文按字母序在前，中文按拼音序在后。详解见 [00 使用说明](00-如何使用本文档.md)、[01 全景总览](01-全景总览.md)、[11 性能](11-性能专项.md) ｜ 返回 [阅读地图](README.md)

| 词 | 人话 |
|---|---|
| API | 程序之间约定的传话规则 |
| Bug | 产品的毛病、程序的错误 |
| CLI | 命令行工具（黑框框打字操作） |
| Debug | 调试：找 bug 的过程 |
| GDPR | 欧盟数据保护条例：全球最严数据法规 |
| GUI | 图形界面（点点点操作） |
| IDE | 集成开发环境：写代码的工作台（如 VS Code） |
| JSON | 数据交换的标准文本格式 `{"名": "值"}` |
| Markdown | 用符号排版文字的轻量格式（本文件就是） |
| RegExp 正则表达式 | 高级查找语法：写一串符号，就能在长文本里批量找到/替换符合规律的内容 |
| SDK | 开发工具包：别人打包好的一整套开发工具 |
| UI | 用户界面（看得见的部分） |
| URL | 网址、链接 |
| XML | JSON 之前的老牌数据格式，标签一对对写 |
| YAML | 比 JSON 更"像人话"的配置文件格式，靠缩进分层、不用括号 |
| 编译器 | 把代码翻译成电脑能直接执行的机器码 |
| 程序 | 写好的代码跑起来的样子 |
| 代码 | 写给电脑看、指挥电脑干活的文字 |
| 断点 | 调试时在代码某行"设卡"，暂停检查现场 |
| 端口 | 电脑上的"门牌号"，一个程序占一个端口提供服务 |
| 个保法 | 中国个人信息保护法：收集信息要告知、同意、可删除 |
| 后端 | 用户看不见的部分（逻辑与数据） |
| 架构 | 代码世界的房屋结构图 |
| 解释器 | 解释型语言"边翻译边跑"的执行者。语言分两派：编译型（如 C/Go）先整本翻译成机器码再跑，快但改一次编一次；解释型（如 Python/JS）边翻译边跑，灵活但稍慢 |
| 技术选型 | 选择语言、框架、数据库的决策过程 |
| 进程 | 正在运行中的一个程序实例 |
| 开源 | 源代码公开，人人可看可用 |
| 客户端 | 用户这一侧的软件（相对服务器而言） |
| 库 | 别人写好的功能集合，借来用 |
| 框架 | 别人搭好的半成品骨架，往里填内容 |
| 前端 | 用户看得见的部分（界面） |
| 软件 | 程序的正式叫法 |
| 线程 | 进程内部的"人手"，多线程 = 多只手同时干活 |
| 依赖 | 项目借用的别人写的库 |
| 隐私政策 | 说明"收集什么数据、拿来干什么"的声明文档 |
| 运行环境 | 程序跑起来所需的基础设施（如 Node.js 环境） |
| 终端 | 打字指挥电脑的黑框框窗口 |
| 字节 | 存储的最小计量单位（1MB = 约 100 万字节） |
