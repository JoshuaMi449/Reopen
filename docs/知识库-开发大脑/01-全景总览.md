## 第 1 章：一个产品是怎么诞生的——全景总览

### 1.1 八大阶段总览

一个产品从"我有一个想法"到"用户用上了"，正规公司会走过八个阶段：

```text
想法
 │
 ▼
① 需求阶段 ──► 搞清楚"到底做什么"
 │
 ▼
② 设计阶段 ──► 画出来"长什么样"
 │
 ▼
③ 技术方案阶段 ──► 定好"用什么做、怎么搭"
 │
 ▼
④ 开发阶段 ──► 动手写代码
 │
 ▼
⑤ 测试阶段 ──► 检查"对不对、好不好"
 │
 ▼
⑥ 运维阶段 ──► 放到服务器上跑起来
 │
 ▼
⑦ 发布阶段 ──► 送到用户手里
 │
 ▼
⑧ 运营迭代阶段 ──► 收集反馈，做下一个版本
 │
 └──────► 回到①，开始新一轮循环
```

### 1.2 八大阶段速览表

| 阶段 | 干什么（人话） | 谁干 | 产出物 | 完事标志 |
|---|---|---|---|---|
| ① 需求 | 搞清楚：给谁用、解决什么问题、做哪些功能 | 产品经理（PM） | 需求文档（PRD） | 需求评审会通过 |
| ② 设计 | 把功能画成界面：先黑白草稿，后上色效果图 | UI/UX 设计师 | 设计稿 | 设计评审通过 |
| ③ 技术方案 | 定语言、定架构、定数据库、定接口 | 架构师/技术负责人 | 技术方案文档 | 技术评审通过 |
| ④ 开发 | 写代码：前端画界面，后端写逻辑 | 前端/后端工程师 | 代码 | 功能开发完成 |
| ⑤ 测试 | 挑毛病：零件单独测、拼起来测、整体点一遍 | 测试工程师（QA） | 测试报告 | 验收通过 |
| ⑥ 运维 | 部署到服务器、配域名、装监控、看日志 | 运维工程师（DevOps） | 线上运行的服务 | 服务稳定运行 |
| ⑦ 发布 | 打包、分发、上线，让用户拿到手 | 全员配合 | 发布版本 | 用户能下载使用 |
| ⑧ 运营迭代 | 收集用户反馈、看数据、排下一版需求 | 产品经理+运营 | 迭代计划 | 进入下一轮循环 |

> ⚠️ **重要认知**：这八个阶段不是"做完一个才做下一个"的流水线，而是会来回反复的。比如测试阶段发现需求定错了，会回到需求阶段改文档——这叫**迭代**。正规团队允许反复，但**不允许跳过**：不写需求就写代码，后面返工的成本是前者的十倍。

### 1.3 团队角色（人话版）

| 角色 | 英文/缩写 | 人话解释 |
|---|---|---|
| 产品经理 | PM（Product Manager） | "产品该做什么"的决策者。写需求文档，回答"为什么做这个功能"。注意：PM 还有另一层意思（Project Manager，项目经理），管进度排期的，别混 |
| UI 设计师 | UI Designer | 管"好不好看"：颜色、字体、按钮长什么样 |
| UX 设计师 | UX Designer | 管"好不好用"：点哪里、怎么跳转、流程顺不顺 |
| 前端工程师 | Frontend Engineer | 写用户看得见的界面部分（网页/桌面窗口里的画面） |
| 后端工程师 | Backend Engineer | 写用户看不见的逻辑部分（数据怎么存、怎么算） |
| 测试工程师 | QA（Quality Assurance） | 专门挑毛病的人，保证质量 |
| 运维工程师 | DevOps / SRE | 管服务器和线上稳定的人，"服务器医生" |
| 架构师 | Architect | 技术方案的设计者，决定"整个项目用什么技术怎么搭" |
| 全栈工程师 | Full-stack Engineer | 前端后端都会写的人 |

### 1.4 一个人 + AI 的模式，怎么映射这些角色

大公司是一群人分工，而个人项目（尤其用 AI 辅助开发）是把这些角色压缩到两个人身上：

| 角色 | 由谁承担 | 人话 |
|---|---|---|
| 产品经理 | **你** | 你定义产品：痛点、功能、优先级，AI 不做这个 |
| 设计师 | AI 出稿 + 你确认 | AI 画界面草图，你用"好不好看、顺不顺手"的感觉来验收 |
| 架构师/前后端 | AI | 技术决策和写代码由 AI 完成，但**决策过程要讲给你听** |
| 测试 | AI 自测 + 你验收 | AI 跑自动检查，你最后亲手用一遍 |
| 运维 | 平台 | 开源项目用 GitHub 托管，不需要自己租服务器 |
| 项目进度管理 | 你 + 文档 | 用"做一步记一步"的台账文档跟踪进度 |

**核心原则：产品侧的判断（做什么、好不好用）永远由你做，技术侧的实现（怎么写、怎么搭）由 AI 做，但 AI 必须把每个技术决策用人话解释到你能拍板为止。**

### 1.5 常见误区

- ❌ **"先写代码，需求后面再说"**——最贵的错误。代码改一行容易，方向错了全白写。
- ❌ **"设计就是美工"**——设计 = 交互（好不好用）+ 视觉（好不好看），一半是逻辑活。
- ❌ **"测试是最后才做的事"**——正规团队从写代码的第一天就在测试。
- ❌ **"上线就结束了"**——上线是运营迭代的开始，大多数产品死于上线后没人管。

### 1.6 单人 vibe coding 的工具链

一个人用 AI（如 Claude Code）开发产品时，工具链分成三张表：**你操作的 App、AI 操作的 CLI、AI 可接的 MCP 插件**。

**① 你（人）需要的 App：**

| 工具 | 干什么 | 装法 |
|---|---|---|
| VS Code | 看代码、验收改动、自己改两行 | 官网下载或 `brew install --cask visual-studio-code` |
| 浏览器 | 验收网页和界面效果 | 自带 |
| GitHub 网页版 | 看仓库、Issue、Release | 无需安装 |
| 终端 Terminal | 跑命令、看日志 | 系统自带 |

**② AI 需要的 CLI（命令行工具）：**

| 工具 | 干什么 | 装法 |
|---|---|---|
| Git | 版本管理（时光机） | macOS 一般自带；没有则 `xcode-select --install` |
| Node.js + npm | 跑 JS 生态（Electron/React/Vite 全靠它） | 官网安装包或 nvm |
| gh（GitHub CLI） | AI 直接操作 GitHub：建仓库、发 Release、传安装包 | `brew install gh` 然后 `gh auth login`（你登录一次） |
| Python 3 | 跑辅助脚本（批处理、图像处理等） | 官网或 `brew install python` |
| Homebrew | Mac 装软件的命令行"应用商店" | 官网一键脚本 |

**③ AI 可接的 MCP（插件，装进 Claude Code 后 AI 获得新能力）：**

| MCP | 干什么 |
|---|---|
| 搜索类（ddg-search 等） | 联网查资料、查文档 |
| GitHub MCP | 更彻底地操作 GitHub：建 repo、管 Issue/PR、发 Release |
| Playwright MCP | 自动打开网页、截图、验收界面 |
| 办公类（飞书等） | 读写办公文档、多维表格 |

**④ 不需要装的**（外行容易误装）：数据库软件（小项目 JSON 文件够用，见[第 13 章](13-数据专项.md)）、Docker 服务器套件（单机应用不需要，见[第 7 章](07-运维阶段.md)）、Xcode 完整版（打 dmg 用 electron-builder 即可，见 [5.3 节](05-开发阶段.md)）。

**⑤ 各章提到的"环节工具"在单人 + AI 模式下谁替代谁**（避免误解"文档里提过的都要装"）：

| 文档提到的工具 | 正规团队用法 | 单人 + AI 模式 | 你要装吗 |
|---|---|---|---|
| Figma | 设计师画设计稿 | **AI 直接出设计稿/HTML 原型**，你只验收好不好看 | ❌ 不需要（想亲手调设计才装） |
| Jira / Trello / Linear | 管需求池和进度 | **双文档机制替代**：知识库（大脑）+ 项目台账（做一步记一步） | ❌ 不需要 |
| Sentry | 收集线上崩溃 | 单机应用先用本地日志；产品发布后崩溃多了再加 | ⏳ 后置 |
| Postman / Apifox | 人肉调试 API 接口 | AI 直接用代码/命令调接口 | ❌ 不需要 |
| Navicat 等数据库软件 | 可视化管数据库 | 用 JSON 文件，没有数据库 | ❌ 不需要 |
| Docker Desktop | 跑容器 | 单机应用没有容器 | ❌ 不需要 |
| Xcode | 写原生应用 | Electron 出 dmg 用 electron-builder | ❌ 不需要 |
| 图床/CDN 控制台 | 托管图片资源 | 有需要时按项目单独配（如 ImgBed） | ⏳ 按需 |

**规律**：本文档讲的是"正规团队完整链路"，其中凡是**纯执行类**的工具（设计、调试、接口、管理），AI 都能替代；凡是**你亲自上手**的工具（看代码的 VS Code、验收的浏览器），才需要装。

**装机口诀**：先跑起来（Node + Git），再连上云（gh + GitHub），最后按需加 MCP。
