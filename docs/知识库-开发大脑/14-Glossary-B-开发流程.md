## 第 14 章：专业术语速查表（Glossary）

### B. 开发流程

> 本类词条：英文按字母序在前，中文按拼音序在后。详解见 [02 需求](02-需求阶段.md)、[08 发布](08-发布阶段.md)、[09 运营](09-运营与迭代.md) ｜ 返回 [阅读地图](README.md)

| 词           | 人话                                                            |
| ------------ | --------------------------------------------------------------- |
| A/B 测试     | 两个版本随机分给两组用户，数据定胜负                            |
| Backlog      | 需求池：待做功能的排队名单                                      |
| Beta/RC      | 公测版 / 发布候选版                                             |
| Changelog    | 每个版本"改了什么"的说明                                        |
| CI/CD        | 机器人自动跑测试（CI）和自动部署（CD）                          |
| Code Review  | 合并前同事逐行审代码                                            |
| Git          | 代码版本管理工具（时光机）                                      |
| GitHub       | 托管 Git 仓库的网站（放代码的地方）                             |
| Hotfix       | 热修复：紧急 bug 火速发的补丁版                                 |
| Issue        | GitHub 上的问题反馈单                                           |
| Monorepo     | 所有项目放一个仓库（Vite 生态主流）；个人项目一般用多仓库更简单 |
| MVP          | 最小可行产品：先做最能解决痛点的功能                            |
| P0/P1/P2     | 优先级：必须有 / 应该有 / 可以有                                |
| PR           | 拉取请求："我的分支做完了，请审阅合并"                          |
| PRD          | 产品需求文档，项目的宪法                                        |
| Release      | GitHub 上的正式发布（可附安装包）                               |
| Roadmap      | 未来版本的路线图                                                |
| Sprint       | 冲刺：敏捷开发的一个工作周期（1-2 周）                          |
| Tag          | 给某个代码存档起的版本名（v1.0.0）                              |
| 迭代         | 一轮一轮的开发周期                                              |
| 估时         | 估算任务工时的动作                                              |
| 灰度发布     | 先放小部分用户试水，再全量                                      |
| 回滚         | 新版本出问题，退回上一版                                        |
| 里程碑       | 交付时间节点                                                    |
| 联调         | 前后端把两边接上一起调试                                        |
| 敏捷开发     | 小步快跑、频繁交付的开发方式                                    |
| 排期         | 估算任务并排出时间表                                            |
| 任务拆解     | 把 PRD 功能拆成可执行的小任务                                   |
| 需求管理工具 | Jira/Trello/Linear 等管需求池和进度的软件                       |
| 需求评审     | 开工前全员对齐 PRD 的会议                                       |
| 验收标准     | "做到什么程度算完"的可验证标准                                  |
| 用户故事     | "作为____我想____以便____"的需求句式                            |
