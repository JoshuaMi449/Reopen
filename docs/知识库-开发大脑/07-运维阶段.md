## 第 7 章：运维阶段（DevOps 的世界）

### 7.1 是什么

运维回答一个问题：**"怎么让它 7×24 小时稳稳跑在线上？"**

> ⚠️ 先说明：**只有需要联网共享数据的服务型产品才有这个阶段**。单机工具（数据都在用户本机）没有服务器可运维——这是单机工具的重大红利。但本章内容值得懂，因为"日志""监控"的概念单机工具也用得上。

### 7.2 标准做法：服务器与部署

| 名词 | 人话 |
|---|---|
| 服务器 Server | 租来的"云端电脑"，24 小时开机，你的程序跑在上面 |
| 云服务商 Cloud Provider | 出租云端电脑的公司：AWS（亚马逊）、阿里云、腾讯云、Google Cloud |
| VPS（Virtual Private Server） | 一台虚拟的独立服务器（便宜入门款） |
| 部署 Deploy | 把代码"运"到服务器上跑起来的过程 |
| Nginx | 最流行的服务器软件：接待访客请求的"前台" |
| Docker | 把程序+环境打包成"集装箱"，到任何服务器都能原样跑 |
| 容器 Container | Docker 打包出的集装箱 |
| K8s（Kubernetes） | 管理成千上万集装箱的调度系统（大厂才需要） |
| 负载均衡 Load Balancer | 访客太多时，把请求分给多台服务器的"分流交警" |
| 反向代理 Reverse Proxy | Nginx 的核心工作：访客找"前台"，前台把请求转给后台的服务——对外只露一个门 |
| CDN | 内容分发网络：把图片、静态文件缓存到全球各地的节点，用户就近取——加载更快 |
| 进程守护 Process Supervisor | "看门人"（pm2/systemd）：服务挂了自动拉起、开机自动启动 |
| 扩容 Scale | 不够用了加服务器（扩容/缩容） |
| 灾备 Disaster Recovery | 灾难预案：机房炸了/数据删错了，怎么快速恢复（异地备份+恢复演练） |

### 7.3 标准做法：域名与证书

| 名词 | 人话 |
|---|---|
| IP 地址 | 服务器的门牌号（如 192.168.1.1） |
| 域名 Domain | 给门牌号起的好记名字（如 example.com） |
| DNS | "域名→门牌号"的全球电话簿 |
| HTTP / HTTPS | 网页传输协议；HTTPS 多一层加密，浏览器地址栏的锁图标 |
| SSL/TLS 证书 | HTTPS 加密要用的"数字锁"，从证书机构申请（有免费版 Let's Encrypt） |
| ICP 备案 | 中国特有：用国内服务器对外提供服务必须先备案（免费但流程要几周）；用海外服务器或纯 GitHub 托管则不需要 |

### 7.4 标准做法：日志体系（重点专项）

**日志（Log）** = 程序的"行车记录仪"：程序每干一件事，就往日志文件里写一行。用户报 bug 时，工程师第一件事就是看日志——**没有日志的 bug 是悬案**。

| 名词 | 人话 |
|---|---|
| 应用日志 | 程序自己写的记录（"用户张三登录成功"） |
| 访问日志 | 谁在什么时候访问了哪个页面 |
| 错误日志 | 出错时的现场记录（错在哪一行、什么原因） |
| 日志分级 Log Level | 记录分轻重：**DEBUG**（调试细节）/ **INFO**（正常流水）/ **WARN**（警告，可能要出事）/ **ERROR**（出错了） |
| 日志轮转 Rotation | 日志文件会越来越大，按天/按大小切割归档，旧的定期删 |
| 日志保留期 Retention | 日志留多久（如 7 天） |

### 7.5 标准做法：监控与告警

| 名词 | 人话 |
|---|---|
| 监控 Monitoring | 实时盯服务健康（响应快不快、内存够不够），用图表展示 |
| 告警 Alert | 出问题自动通知人（短信/电话/飞书机器人） |
| 崩溃收集 Crash Reporting | 应用闪退时自动把"案发现场"上报给收集平台 |
| Sentry | 最流行的崩溃收集服务（开源、有免费额度） |
| 可用性 SLA | "保证 99.9% 时间可用"的服务承诺（大厂标准 99.99%） |

### 7.6 标准做法：CI/CD 自动化流水线（重点专项）

**CI/CD** = 把"测试→构建→部署"这些重复劳动交给机器人自动干。

| 名词 | 人话 |
|---|---|
| CI（Continuous Integration）持续集成 | 代码一提交，机器人自动跑测试——早发现早治疗 |
| CD（Continuous Delivery/Deployment）持续交付/部署 | 测试通过后，机器人自动打包甚至自动上线 |
| GitHub Actions | GitHub 自带的机器人平台：在 `.github/workflows/*.yml` 里写"提交后帮我跑这些命令" |
| 流水线 Pipeline | 一串自动化步骤的总称（提交→装依赖→测试→打包） |
| 自动打包 | CI 机器人在云端自动跑 `npm run build`、`npm run dist`，产出安装包 |

**CI/CD 对开源项目的价值**：每次提交自动测试、自动出安装包，人不用管——这正是 [5.4 节](05-开发阶段.md)说的"CI 配置文件"的用处。

### 7.7 常见误区

- ❌ **不记日志**——出了 bug 只能靠猜。至少记：启动、关键操作、出错现场。
- ❌ **日志里存密码**——日志可能被泄露，敏感信息要脱敏。
- ❌ **小项目全套上 Docker + K8s**——杀鸡用核弹，运维复杂度吃光开发时间。
