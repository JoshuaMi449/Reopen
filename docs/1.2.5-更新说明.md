# Reopen 1.2.5 更新内容

**历史图卡顿的真正原因找到了，这版修的是它。**

## 真因：每秒推送 35MB

历史数据一直是这么送的：主进程每秒把**整段 30 天存档**序列化一遍，通过 IPC 发给面板和历史图两个窗口。

在本机实测的数字：

```
system-history.json  =  35.7 MB / 87,366 个样本 / 27.8 天
推送频率             =  每秒 1 次（startSystemInfoFeed）
```

用 Chrome 调试协议对运行中的 app 采样，渲染进程的表现是：

```
长任务 6 个，累计 3130ms
  +3292ms → 502ms
  +4300ms → 578ms   ← 间隔 1008ms
  +5299ms → 527ms   ← 间隔  999ms
  +6305ms → 511ms   ← 间隔 1006ms
JS 堆 440.6 MB
```

**每隔 1000ms 一次、每次约 500ms 的主线程卡死——渲染进程有一半时间是死的。** 鼠标滑动时正好撞上这些卡顿，所以感觉是"滑不动"，但它跟鼠标、跟图表渲染其实毫无关系：不动鼠标它也在每秒发生。

同一次采样还做了对照实验：在图表上扫和在非图表的标题区扫（同样派发鼠标事件、只是一个有处理器一个没有），帧时间中位数**完全一样**。也就是说：

- ❌ `getBoundingClientRect()`（1.2.3 改的）不是原因
- ❌ React 重建 480 个 SVG 元素（1.2.4 改的）不是原因
- ✅ 每秒 35MB 的 IPC 推送才是

## 修复

- **整段存档只在窗口加载时发一次**，不再每秒重发。
- **每秒推送改为只带增量**：实时窗口（最近 10 分钟、1 秒分辨率，约 600 条）+ 新增的存档样本（通常 0~1 条）。
- 存档增量按时间戳去重，重复收到已有样本不会重复追加；水位只在首次对齐，面板窗口跨显示/隐藏常驻时不会丢掉隐藏期间的样本。

每秒过 IPC 的数据量从 **约 35MB 降到约 250KB**（约 1/140）。

## 保留

1.2.4 把四种大图的柱子拆成 `memo` 组件本身的改动保留——它没有坏处，只是不是瓶颈所在。
