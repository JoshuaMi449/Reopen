# Reopen（VC复活点）PRD 与执行台账

> 本文件是 Reopen 项目的**需求文档 + 执行台账**（双文档机制中的文档 B）。所有产品决策来自 2026-08-18~19 与用户的深度产品交流（13+ 轮逐项确认）。
> 通用知识（PRD 是什么、名词解释等）见 [知识库-开发大脑](知识库-开发大脑/README.md)。

## 一、产品概述

| 项                            | 内容                                                                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 产品名                        | **Reopen**（界面与仓库统一只显示 Reopen；中文别称"VC复活点"仅用于文档与介绍）                                                |
| 一句话简介（GitHub 仓库描述） | Restart your Mac without losing your projects                                                                                |
| 痛点                          | 重启 Mac 后，vibecoding 产物（localhost 服务、散落的 html 文件）"丢失"——服务不在了、文件找不到了、自制启动器想不起来在哪     |
| 解决方案                      | 一个桌面应用：**登记你的项目 → 一键启动/停止 → 查看状态与日志 → 打开 Reopen 自动复活自启项**。既是管理器，也是自动化工具     |
| 形态                          | macOS 窗口应用，dmg 包分发，开源发布 GitHub（`JoshuaMi449/Reopen`，MIT 协议），未来兼容 Windows                              |
| 技术栈                        | Electron + React + TypeScript（选型理由：TypeScript 是 GitHub 第一大语言、AI 编写最熟练、跨平台 dmg+exe 一条链路、生态成熟） |

**核心概念**：两层"自动"机制

- **开机自启（电脑层）**：Reopen 自己加入 Mac 登录项，开机自动打开
- **自启项（软件层）**：打开 Reopen 后，自动启动你放进"自启项"里的项目
- 两层叠加 = 全自动复活链：Mac 开机 → Reopen 打开 → 项目全部自动拉起

## 二、目标用户

| 用户       | 描述                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 主要用户   | 用 AI 做开发（vibe coding）的非专业程序员——自己做的项目散落在电脑各处，重启后需要逐个找回 |
| 开源后扩展 | 有同样痛点的独立开发者、尝鲜用户                                                          |

## 三、功能需求

> 第一版**全功能一次做完**（用户拍板：不分批）。以下所有功能均为 P0。

### 3.1 项目类型（两种）

| 类型         | 定义                                        | 管理能力                          |
| ------------ | ------------------------------------------- | --------------------------------- |
| **本地服务** | localhost 服务（如 `npm run dev` 起的网站） | 启动命令、端口、日志、状态        |
| **网页文件** | 散落的 html 文件/文件夹                     | 自动起临时 http 服务 + 浏览器打开 |

> 「应用」类型（.app 文件）第一版**砍掉**（用户拍板）。原因：.app 天生不丢（启动台/桌面躺着）、无管理点（无命令/端口/日志）、进程监控复杂。拖入 .app 时的兜底行为见 3.2。

### 3.2 添加项目（拖拽自动识别）

| 行为                   | 规则                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| 拖入**文件夹**         | 识别：含 package.json → 本地服务；含 html 文件 → 网页文件                                                       |
| 拖入**单个 html 文件** | 识别为网页文件                                                                                                  |
| 拖入 **.app 文件**     | 提示"第一版不支持应用类型" → 询问是否解析 → 是服务/网页包装器则转成对应类型登记；解析不出提示失败               |
| 识别失败/猜错          | 弹确认表单，类型预选可改，永不卡死                                                                              |
| 表单自动填写           | **全自动猜**：名称取文件/文件夹名、路径自动填、启动命令从 package.json scripts 猜、端口自动猜——你只需确认或修改 |

**确认表单字段**：

| 字段           | 本地服务          | 网页文件            |
| -------------- | ----------------- | ------------------- |
| 名称           | 自动猜            | 自动猜              |
| 路径           | 自动填            | 自动填              |
| 启动命令       | 自动猜（scripts） | —（自动起临时服务） |
| 端口           | 自动猜            | 可指定（留空自动分配） |
| 启动后开浏览器 | 滑动按钮，默认关  | 滑动按钮，默认关    |
| 备注           | 手填              | 手填                |
| 标签           | 手填/选           | 手填/选             |

### 3.3 主界面（侧边栏 + 列表 / 卡片，双视图）

**侧边栏**：全部 / 最近使用 / 服务 / 网页 / 标签（分类浏览）

**列表行**（默认视图）：状态圆点（🟢运行/⚪停止）+ 名称 + 端口号 + 上次启动时间 + 类型图标 + 备注 + 启动/停止按钮

**卡片视图**：可切换，同数据不同排版

**顶部工具栏**：搜索框 + 标签（访达式彩色标签分类）+ 视图切换 + 「+」添加按钮 + 设置齿轮

**排序**：访达式三选一随时切换——手动拖拽 / 最近使用 / 名称

**右键菜单**（列表行/卡片）：启动 / 停止 / 在浏览器打开 / 编辑 / 删除 / 加入自启项。删除弹确认框，文案强调"**只从 Reopen 移除登记，不删你电脑上的原文件**"

**明确没有**：「全部启动」按钮（用户拍板不要——复活靠自启项自动拉 + 菜单栏逐个点）

### 3.4 启动 / 停止 / 状态与日志

| 项       | 行为                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 启动     | 点行尾按钮；服务类起进程，网页类起临时服务                                                                       |
| 停止     | 停掉对应进程（网页类杀掉临时服务）                                                                               |
| 启动失败 | **不重试**；卡片/行标红 + 右上角通知**带失败原因**（如"端口3459已被占用"），点通知展开该项目的日志面板看完整错误 |
| 日志查看 | **行内展开面板**（点列表行展开）：状态、端口、命令、实时日志、停止/重启/编辑按钮                                 |

### 3.5 自启项（软件层自动启动）

| 项       | 行为                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 总开关   | 偏好设置→通用里，**默认开启**，旁边白话小字解释：_打开软件后，自动启动你放进来的产品_（关闭=没有这个功能，顶部 icon 不显示） |
| 开启后   | 主界面上方多出一个 icon，点开**气泡面板**（浮在主界面上方的小面板）                   |
| 加入方式 | 把列表行**拖进气泡面板**即加入                                                        |
| 同步显示 | 管理所有项目的界面里，在自启项里的项目**打勾**同步显示                                |
| 触发     | 打开 Reopen 时自动启动面板内所有项目                                                  |

### 3.6 偏好设置（6 组，Mac 标准式：左侧分组 + 右侧内容）

| 分组       | 设置项                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| **通用**   | 自启项总开关（白话解释）、开机自启（Reopen 加入 Mac 登录项）、关闭时最小化到托盘、默认浏览器、语言（中/英）、通知方式 |
| **外观**   | 主题配色、浏览（列表间距/卡片大小调整）                                                                               |
| **菜单栏** | 启用开关（**默认开启**）、样式自定义                                                                                  |
| **快捷键** | 全局唤起窗口（默认 **⌥+R**，可改）、快捷启动项目（**不设默认**，自己绑）、应用内快捷键（⌘N 添加/⌘F 搜索等）           |
| **资料库** | 所有产品的源文件路径一览、数据备份导出/导入                                                                           |
| **关于**   | 版本号、检查更新、GitHub 地址、开源协议                                                                               |

### 3.7 菜单栏

- 默认开启（Mac 顶栏小图标）
- 点击弹出小面板：**项目列表快速启停**（带状态圆点，点一下启/停）+ 打开主窗口 / 退出

### 3.9 新手引导（Onboarding / Guided Tour）

- 流程：打开 → **欢迎界面**（介绍+开始按钮）→ 进入主界面后**主界面变暗（蒙层）** → **弹出引导窗口分步讲解** → 上一步/下一步/跳过按钮
- 引导步骤（4 步 + 收尾）：
  1. 指向侧边栏——「按类型和标签浏览你的项目」
  2. 指向列表行——「点一下启动/停止，点开行内面板看日志」
  3. 指向顶部「+」——「把项目文件夹或 html 拖进窗口，自动识别登记」
  4. 指向自启项 icon——「拖进去，以后打开 Reopen 自动复活」
  5. 收尾——「⌥+R 随时唤出窗口」
- **不放示例项目**（用户拍板：引导教完直接拖真实项目，列表干净）

## 四、非功能需求

| 类别   | 要求                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 性能   | 应用启动 ≤ 3 秒；列表滚动流畅；日志实时刷新不卡界面                                        |
| 兼容   | macOS 12 以上（待验证后确定）；预留 Windows 结构（Electron 天然跨平台）                    |
| 数据   | 项目清单存 JSON 文件，位置 `~/Library/Application Support/Reopen/`；不联网、不上传任何数据 |
| 安全   | 存储的启动命令只在本机执行；不收集用户信息                                                 |
| 稳定性 | 单例锁（防双开）；主进程保持轻量；项目进程与应用进程分离（项目挂了不影响 Reopen）          |

## 八、技术方案概要（技术侧拍板）

| 项       | 决策                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------ |
| 架构     | Electron 双进程：主进程管系统交互（进程管理、文件、菜单栏/托盘、登录项），渲染进程 React 画界面；界面层/逻辑层分离 |
| 模块划分 | 项目管理 / 进程启动 / 端口检测（健康检查） / 配置存储（JSON） / 界面，五模块                                       |
| 进程管理 | 服务类用 child_process 拉起并记录 PID 与进程树，停止时整树终止；网页类起临时 http server，端口自动分配             |
| 端口检测 | 启动后轮询端口就绪（健康检查），超时判失败并捕获错误输出作为"失败原因"                                             |
| 存储     | 项目清单 projects.json + 设置 settings.json，存 `~/Library/Application Support/Reopen/`                            |
| 打包     | electron-builder 出 dmg；electron-updater 检查 GitHub Releases 更新                                                |
| 系统集成 | 单例锁、launchd 登录项（开机自启开关）、托盘/菜单栏、全局快捷键（⌥+R）                                             |
| 质量     | TypeScript 严格模式 + ESLint + Prettier；单元测试覆盖核心模块；GitHub Actions 自动构建                             |
